# obix-cli-create

> Previous name: `@obinexusltd/obix-cli-create` — OBIX packages are named without an npm scope since decision D-102 (2026-09-29); the package, its version and its exports are unchanged.

> Scaffold an **OBIX Heart UX** application in seconds.

```bash
npx obix-cli-create
# or (after global install)
obix-cli-create
```

---

## Usage

```bash
# Interactive (recommended)
npx obix-cli-create

# With a project name
npx obix-cli-create my-app

# Choose template upfront
npx obix-cli-create my-app --template node
npx obix-cli-create my-site --template html

# Non-interactive, all defaults
npx obix-cli-create my-app --yes
```

---

## Templates

### `node` (default)

Full-stack TypeScript application:

```
my-app/
├── src/
│   ├── core/       ← runtime.ts · types.ts · policies.ts
│   ├── ui/         ← renderer.ts · main.ts
│   ├── server/     ← app.ts (Express) · database.ts (node:sqlite)
│   └── cli/        ← index.ts (commander + inquirer)
├── package.json
├── tsconfig.json
└── .gitignore
```

**Get started:**
```bash
cd my-app
npm install
npm run dev       # → http://localhost:3000
npm run cli -- --help
```

### `html`

Zero-dependency browser app — no build step:

```
my-site/
├── index.html
├── styles.css
├── app.js
├── package.json
└── .gitignore
```

**Get started:**
```bash
cd my-site
npx serve .       # → http://localhost:3000
```

## What every OBIX app includes

Both templates implement the OBIX Heart UX patterns:

| Pattern | What it means |
|---|---|
| **Controller → Control → Controllee** | Input → state transition → DOM/DB output |
| **Data-Oriented Programming** | State is a plain object; actions are pure functions |
| **#NoGhosting policy** | Every open item must have an owner; policy runs on every change |
| **Accessibility** | 48 px touch targets (OBIX design policy; WCAG 2.2 asks 24 px at AA, 44 px at AAA), visible focus rings, a skip link, ARIA live regions — automated checks only, see *Verification* |

## Options

Synopsis: `obix-cli-create [project-name] [--template node|html] [--yes]`


| Flag | Description |
|---|---|
| `[project-name]` | Directory name / package name for the new project |
| `-t, --template <name>` | `node` (default) or `html`; anything else is refused (exit 2) |
| `--version` | The version of this package (read from its package.json) |
| `-y, --yes` | Skip all prompts, accept defaults |

## Verification (Stage 6)

Run by `npm test` (real process) and `tests/browser/scaffold-html.browser.test.mjs` (Microsoft Edge, real HTTP server):

- Scaffolding both templates, token interpolation, the scoped-name directory, refusing an existing directory, refusing an unknown template, `--version`.
- `html`: loads with no console error, failed request or 4xx; the skip link works; adding, starting, completing and deleting an item change the stats and the #NoGhosting violation; **axe-core finds no violation** in the empty and populated states at 1280 and 375 px; every button and control is at least 48 px. (Fixed while verifying: six contrast failures, an in-text link distinguished by colour only, 36 px buttons, a footer link to a document the scaffold does not contain, a favicon 404.)
- `node`: the policy engine (`src/core/types.ts`, `policies.ts`) compiles with the workspace TypeScript and its #NoGhosting policy is exercised. **Not verified:** `runtime`, `server`, `cli` and `ui` — they need `uuid`, `express`, `commander`… installed from a registry, which was not done. (Fixed: the template asked for `obix@^0.1.0`, which does not exist and which no source file imports.)
- Not performed: manual keyboard or screen-reader testing; browsers other than Edge.
